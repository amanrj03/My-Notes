## 1. Octal and Hexadecimal Expansions

### 1.1 Why powers of 2 matter in computer science
Computers operate natively on bits (binary, base 2). However, long strings of 0s and 1s are cumbersome for humans to read and write. Because:

\[ 8 = 2^3 \qquad\text{and}\qquad 16 = 2^4, \]

every octal digit corresponds to exactly a block of 3 binary digits, and every hexadecimal digit corresponds to exactly a block of 4 binary digits.

### 1.2 The Octal System (Base 8)
In base 8, the allowable digits are:

\[ \{0, 1, 2, 3, 4, 5, 6, 7\}. \]

The base-8 expansion of an integer \(n\) is:

\[ n = a_k 8^k + a_{k-1} 8^{k-1} + \cdots + a_1 8 + a_0, \qquad 0 \le a_i \le 7. \]

### 1.3 The Hexadecimal System (Base 16)
In base 16, sixteen digits are needed. The decimal digits 0 through 9 are used, followed by the first six letters of the English alphabet:

## 2. Fast Block Conversions Between Binary, Octal and Hexadecimal

### 2.1 Binary to Octal Conversion
To convert a binary numeral to octal:
1. Group the binary digits into blocks of **three bits**, starting from the **right** (least significant bit).
2. If the leftmost block has fewer than three bits, pad it with leading zeros.
3. Replace each 3-bit group with its corresponding octal digit (0 to 7).

#### Worked Example:
Convert \((1111010111100)_2\) to octal:
- Grouping into 3 bits from the right:
  \[ 001 \quad 111 \quad 010 \quad 111 \quad 100 \]
- Replacing each group:
  \[ 001_2 = 1, \quad 111_2 = 7, \quad 010_2 = 2, \quad 111_2 = 7, \quad 100_2 = 4 \]
- Therefore:
  \[ (1111010111100)_2 = (17274)_8. \]

### 2.2 Binary to Hexadecimal Conversion
To convert a binary numeral to hexadecimal:
1. Group the binary digits into blocks of **four bits**, starting from the **right**.
2. Pad the leftmost block with leading zeros if necessary.
3. Replace each 4-bit group with the matching hexadecimal digit (0-9, A-F).

#### Worked Example:
Convert \((1111010111100)_2\) to hexadecimal:
- Grouping into 4 bits from the right:
  \[ 0001 \quad 1110 \quad 1011 \quad 1100 \]
- Replacing each group:
  \[ 0001_2 = 1, \quad 1110_2 = \text{E} (14), \quad 1011_2 = \text{B} (11), \quad 1100_2 = \text{C} (12) \]
- Therefore:
  \[ (1111010111100)_2 = (1\text{EBC})_{16}. \]

### 2.3 Octal to Hexadecimal Conversion
To convert between octal and hexadecimal, use **binary as an intermediate bridge**:
\[ \text{Octal} \xrightarrow{\text{expand each digit to 3 bits}} \text{Binary} \xrightarrow{\text{regroup into 4 bits}} \text{Hexadecimal} \]

#### Worked Example:
Convert \((753)_8\) to hexadecimal:
1. Expand each octal digit to 3 bits:
   \[ 7 \to 111, \quad 5 \to 101, \quad 3 \to 011 \implies (111101011)_2 \]
2. Regroup into 4-bit blocks from right:
   \[ 0001 \quad 1110 \quad 1011 \]
3. Convert to hex:
   \[ 0001_2 = 1, \quad 1110_2 = \text{E}, \quad 1011_2 = \text{B} \implies (1\text{EB})_{16}. \]

## 3. General Base Conversion Algorithm

### 3.1 Algorithm: Constructing Base-\(b\) Expansion
Rosen Section 4.2 presents the formal algorithm for constructing the base-\(b\) expansion of an integer \(n\).

**Algorithm 1: Base \(b\) Expansion**
- **Input:** Positive integer \(n\), integer base \(b > 1\).
- **Procedure:**
  \[ q := n \]
  \[ k := 0 \]
  **while** \(q \ne 0\):
  \[ a_k := q \bmod b \]
  \[ q := \lfloor q / b \rfloor \]
  \[ k := k + 1 \]
- **Output:** The base-\(b\) expansion \((a_{k-1} a_{k-2} \ldots a_1 a_0)_b\).

### 3.2 Complexity of Base Conversion
To convert an integer \(n\) to base \(b\), the number of divisions performed is:

\[ k = \lfloor \log_b n \rfloor + 1. \]

Each division takes \(O(1)\) word operations or \(O(\log^2 n)\) bit operations. Thus, the algorithm requires \(O(\log_b n)\) arithmetic operations.

## 4. The Number of Digits in Base \(b\)

A foundational theorem in number theory and computer science states:

\[ \boxed{\text{Number of digits of } n \text{ in base } b = \lfloor \log_b n \rfloor + 1.} \]

### 4.1 Proof of the Digit-Count Formula
If an integer \(n\) has \(k\) digits in base \(b\), its representation is:
\[ n = a_{k-1} b^{k-1} + \cdots + a_1 b + a_0, \qquad a_{k-1} \ne 0. \]
The smallest integer with \(k\) digits is \(b^{k-1}\) (i.e. \(10\ldots0_b\)), and the largest integer with \(k\) digits is \(b^k - 1\). Therefore:
\[ b^{k-1} \le n < b^k. \]
Taking the base-\(b\) logarithm across the inequality:
\[ k - 1 \le \log_b n < k. \]
By definition of the floor function, this means:
\[ k - 1 = \lfloor \log_b n \rfloor \implies k = \lfloor \log_b n \rfloor + 1. \]

### 4.2 Ratio of Digit Lengths Between Different Bases
If an integer \(n\) requires \(D_2\) digits in binary and \(D_{16}\) digits in hexadecimal:
\[ D_{16} = \left\lceil \frac{D_2}{4} \right\rceil. \]
Similarly, for octal:
\[ D_8 = \left\lceil \frac{D_2}{3} \right\rceil. \]

## 5. Modular Exponentiation Algorithm (Preview)
In cryptography, we frequently calculate \(b^n \bmod m\) where \(n\) is thousands of bits long. We express \(n\) in binary:
\[ n = \sum_{i=0}^{k-1} a_i 2^i, \qquad a_i \in \{0, 1\}. \]
Then:
\[ b^n = b^{\sum a_i 2^i} = \prod_{a_i=1} b^{2^i} \pmod m. \]
This repeated squaring algorithm runs in \(O(\log n)\) multiplications instead of \(O(n)\), enabling modern RSA and Diffie-Hellman cryptosystems!
