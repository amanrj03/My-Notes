Topic 1: Introduction to the Bitcoin Network

1.1 First, what is a network?

Before understanding the Bitcoin network, let's understand the meaning of a computer network.

A computer network is a collection of computers and devices connected to each other so that they can exchange information and resources.

For example, suppose you and your friend are connected to the same Wi-Fi network.

  • Your computer can communicate with another computer.
  • You can send files.
  • You can share information.
  • You can access shared resources.

The internet is a much larger network connecting computers around the world.

Bitcoin also uses the internet to connect computers, but its purpose is different: these computers cooperate to maintain and use the Bitcoin system.

1.2 What is the Bitcoin network?

The Bitcoin network is a peer-to-peer (P2P) network in which participating computers, called nodes, communicate with each other to exchange, verify and propagate Bitcoin transactions and blocks.

Your teacher's PPT gives three main activities performed by Bitcoin nodes:

  1. Performing transactions.
  2. Verifying and propagating transactions and blocks.
  3. Producing blocks through mining (for nodes that perform mining).

The textbook also describes the Bitcoin network as a P2P network in which nodes verify and propagate transactions and blocks, while miners produce blocks.

Let's understand this with a simple example.

Example: Aman sends Bitcoin to Rahul

Suppose Aman wants to send 0.5 BTC to Rahul.

What happens?

  1. Aman's wallet creates a transaction.
  2. The transaction is sent to a Bitcoin node.
  3. That node checks whether the transaction follows Bitcoin's rules.
  4. The node shares the transaction with its connected peers.
  5. Other nodes receive and relay it.
  6. Miners may select the transaction and include it in a block.
  7. The new block is shared with the network.
  8. Other nodes verify the block.

Notice something important: there is no single central bank server that must approve and record this payment.

Instead, participating nodes communicate and independently apply Bitcoin's rules.

1.3 Why does Bitcoin need a network?

Imagine Bitcoin had only one computer maintaining all transactions.

If that computer stopped working, the whole system could become unavailable. If someone controlled that computer, they could potentially control the recordkeeping process.

Bitcoin uses a distributed P2P network to avoid relying on one central computer.

The network provides:

Purpose Explanation
Transaction propagation Shares transactions with other nodes.
Transaction verification Checks whether transactions follow protocol rules.
Block propagation Shares newly created blocks.
Block verification Checks whether blocks are valid.
Decentralisation Avoids dependence on a single central server.
Network availability Other participating nodes can continue communicating when some nodes disconnect.

1.4 Important: Bitcoin network vs Bitcoin blockchain

These two terms are related but are not the same.

Bitcoin network Bitcoin blockchain
A communication system connecting Bitcoin nodes. The ordered ledger of Bitcoin blocks.
Allows nodes to exchange transactions and blocks. Stores the accepted transaction history.
Includes nodes, peer connections and network messages. Includes blocks, headers and transactions.
Helps distribute information. Records the history according to consensus rules.

Easy example to remember:

Think of a classroom.

  • The students communicating with each other represent the Bitcoin network.
  • The official record book maintained according to the classroom rules represents the blockchain.

The network helps distribute information; the blockchain records the accepted history.

Topic 2: Peer-to-Peer (P2P) Network Architecture

This is one of the most important foundations of the Bitcoin network.

2.1 What is a peer-to-peer network?

A peer-to-peer network is a network architecture in which computers, called peers, communicate directly with one another and share information without depending on a central server for every communication.

A computer participating in this network is called a peer or node.

Let's understand it through two examples.

Example A: Centralised network

Imagine a company where all employees must send files through one central server.

Central server
Employee A
Employee B
Employee C
Every employee depends on the central server.

Example B: Peer-to-peer network

Now imagine that employees can communicate directly with one another.

Peer A
Peer B
Peer C
Peer D
Peer E
Peer F
Illustrative peers communicating directly through network connections.

There is no single central computer that must handle every communication.

Bitcoin uses this second architecture.

Centralised Client-Server Topology vs. Decentralised P2P Mesh

Contrasting single-point-of-failure architectures with resilient, distributed peer-to-peer networks
Centralised Client-Server Network
Central Server (Single Point of Failure)
↑↓ Client A ↑↓ Client B ↑↓ Client C
  • Every client depends strictly on the central bank/server.
  • If the central server fails or is seized, the entire system shuts down.
  • Subject to censorship, single-point congestion, and single-target hacks.
Decentralised Peer-to-Peer Mesh (Bitcoin)
Peer A ↔ Peer B Peer B ↔ Peer C
Peer D ↔ Peer E Peer E ↔ Peer F
  • Every peer communicates directly with multiple connected neighbors.
  • Nodes can freely join, leave, or crash without disrupting the network.
  • Transactions and blocks propagate via gossip flooding across all paths.

2.2 How does P2P communication work in Bitcoin?

Suppose Node A receives a new Bitcoin transaction.

  1. Node A checks the transaction.
  2. Node A announces information about it to connected peers.
  3. Interested peers request the transaction data if they do not already have it.
  4. Those peers can relay the transaction to their own peers.
  5. The transaction spreads across the network.

This is commonly described as gossip-style propagation.

In simple language, information spreads from one computer to its connected computers, which then share it further.

2.3 Important characteristics of Bitcoin's P2P network

1. Decentralised communication

No single central server is required to relay all Bitcoin transactions and blocks.

2. Distributed participation

Many computers participate in maintaining and using the network.

3. Direct peer communication

Nodes establish connections with other nodes and exchange protocol messages.

4. Dynamic network

Nodes can join, leave or become temporarily unavailable.

5. Information propagation

Transactions and blocks are relayed through connected peers.

6. Fault tolerance

The network does not depend on one particular node remaining online.

2.4 What is gossip protocol?

A gossip protocol is a method of distributing information through a network by sharing it with selected peers, who then share it with their peers.

Think of a college announcement.

  • A teacher tells five students.
  • Those students tell other students.
  • The announcement spreads throughout the college.

Bitcoin uses peer-to-peer information propagation mechanisms to distribute transactions and blocks.

Important distinction: gossip is a general description of propagation behaviour, not the name of a single Bitcoin transaction message.

Topic 3: What is a Bitcoin Node?

3.1 Definition of a node

A Bitcoin node is a computer running Bitcoin software that participates in the Bitcoin network by communicating with other nodes and performing one or more Bitcoin-related functions.

In simple language, any computer running Bitcoin software and participating in the network can be called a Bitcoin node.

For example:

  • A computer that stores and verifies the blockchain.
  • A computer that receives and relays transactions.
  • A computer that downloads blockchain headers.
  • A computer that performs mining.

These are different kinds of participation.

3.2 Main functions of Bitcoin nodes

Your teacher's PPT and textbook identify the following major functions.

Function Explanation
Wallet Manages keys and helps users create and receive transactions.
Miner Produces candidate blocks and performs Proof of Work.
Blockchain storage Stores blockchain data.
Network routing Communicates with peers and relays transactions and blocks.

The textbook explains that a full Bitcoin node can perform these four functions. However, not every node needs to perform all of them.

Let's understand them individually.

1. Wallet function

A wallet helps a user manage Bitcoin keys and create transactions.

Example: Aman uses a wallet to send 0.1 BTC to Rahul.

2. Mining function

A mining node constructs candidate blocks and performs Proof of Work.

Example: A miner searches for a block hash satisfying the current difficulty target.

3. Blockchain storage function

A node stores blockchain data so it can validate and access the transaction history.

Example: A full node downloads and verifies blocks.

4. Network routing function

A node communicates with other peers and relays transactions and blocks.

Example: Node A receives a transaction and forwards it to Node B.

3.3 Does every Bitcoin node perform all four functions?

No.

This is a very important point.

A Bitcoin network contains different kinds of nodes. Some store the entire blockchain, some operate lightweight wallets, and some perform mining.

The functions depend on the type of node and its software configuration.

Topic 4: Types of Bitcoin Nodes

Your teacher's PPT highlights two main types:

  1. Full nodes
  2. Simple Payment Verification (SPV) nodes

The textbook also discusses solo miners, mining nodes and mining-pool protocol servers.

Let's understand all of them.

4.1 Full node

A full node is a Bitcoin node that independently validates blocks and transactions according to Bitcoin's consensus rules.

A full node downloads and maintains the blockchain data necessary for its operation.

It checks whether transactions and blocks follow the Bitcoin protocol.

Example

Suppose Aman runs Bitcoin Core on his computer.

His node:

  1. Connects to other Bitcoin peers.
  2. Downloads blockchain data.
  3. Verifies blocks and transactions.
  4. Maintains its blockchain state.
  5. Relays valid transactions and blocks.

This is an example of a full-node setup.

Functions of a full node

  • Maintains blockchain data.
  • Independently verifies blocks and transactions.
  • Communicates with other nodes.
  • Relays transactions and blocks.
  • Can support wallet functionality.
  • May also be configured to mine, although mining is not required to be a full node.

4.2 SPV node — Simple Payment Verification

An SPV node is a lightweight Bitcoin client that verifies whether a transaction is included in a block without downloading and independently validating the entire blockchain.

This is a very important concept.

Imagine that you want to use Bitcoin on your mobile phone.

Downloading and storing the entire blockchain may be inconvenient because it requires storage, bandwidth and processing resources.

An SPV wallet reduces these requirements.

How does an SPV node work?

  1. It connects to full nodes.
  2. It downloads block headers instead of the complete blockchain.
  3. When it needs to check a transaction, it requests the relevant transaction information.
  4. It receives a Merkle proof.
  5. It checks whether the transaction is included in a block by verifying the Merkle proof against that block's Merkle root.

Let's understand this with an example.

Suppose a block contains 1,000 transactions.

A full node downloads and validates the block's transactions.

An SPV client does not need to download all 1,000 transactions merely to check whether one particular transaction is included.

Instead, it can obtain the relevant transaction and its Merkle proof.

SPV verification
SPV wallet
Requests proof of a transaction
↓
Full node
Provides transaction data and Merkle proof
↓
SPV client checks the Merkle proof
↓
Checks inclusion against the block header's Merkle root

Advantages of SPV nodes

  1. Require less storage.
  2. Use less bandwidth than downloading the entire blockchain.
  3. Are suitable for mobile devices.
  4. Allow lightweight transaction-inclusion verification.

Limitations of SPV nodes

  1. Do not independently validate every transaction and block.
  2. Depend on full nodes for some transaction information.
  3. Provide less independent verification than a fully validating node.
  4. Can have privacy limitations because requests to peers may reveal which transactions or addresses a user is interested in.

Very important exam point: SPV verifies transaction inclusion using Merkle proofs and block headers. It does not provide the same independent validation as a full node.

4.3 Full node vs SPV node

Full Node vs. SPV Lightweight Node Architecture

Comparing complete consensus verification with lightweight header-only verification
Full Node (Core Backbone)

  • Full Rule Validation: Validates every signature, UTXO, and consensus rule autonomously.

  • Resource Demands: Requires high bandwidth, storage & CPU.

4.4 Solo mining node

A solo mining node is a node that performs mining independently rather than participating in a mining pool.

It can maintain blockchain data, communicate with peers and produce candidate blocks.

The miner receives the block reward if its block is accepted, subject to the protocol rules.

4.5 Mining node

A mining node is a node that performs mining-related functions.

Some mining setups focus mainly on computing hashes and may rely on other software or services for blockchain and network functions.

4.6 Mining-pool protocol server

The textbook also discusses mining-pool protocol servers.

These servers coordinate mining-pool work using protocols such as Stratum.

A mining pool combines the computational efforts of multiple miners. The server distributes work and receives the miners' submitted results.

We'll understand Stratum more clearly later in this module.

Topic 5: Bitcoin Network Protocol

Now that we understand nodes, the next question is:

How do these computers communicate with each other?

They need a common set of communication rules.

That set of rules is called a network protocol.

5.1 What is a network protocol?

A network protocol is a set of rules that defines how computers communicate and exchange information over a network.

For example, imagine two people speaking different languages.

One speaks only Hindi, and the other understands only English.

Communication becomes difficult.

Similarly, computers need agreed formats, commands and rules to exchange information.

Bitcoin uses its own P2P protocol to define how nodes communicate.

5.2 Bitcoin P2P protocol

The Bitcoin P2P protocol defines:

  • How nodes establish connections.
  • How nodes introduce themselves.
  • How peers discover other peers.
  • How transactions are announced and requested.
  • How blocks are announced and requested.
  • How blockchain data is synchronised.
  • How connections are checked and maintained.

Your teacher's PPT lists 27 types of protocol messages in its material. The exact set of supported messages can change with protocol versions and software updates.

The important exam task is to understand the purpose of the main messages.

5.3 What is a magic value?

The textbook explains that a Bitcoin network is identified by a magic value.

A magic value is a special identifier in the message structure that helps a node identify which Bitcoin network a message belongs to.

The textbook lists these examples:

Network Magic value (hexadecimal)
Main network 0xD9B4BEF9
Testnet 0xDAB5BFFA
Testnet3 0x0709110B

Why is this needed?

Imagine a node accidentally receives a message belonging to another Bitcoin network.

The magic value helps identify the message's intended network.

Remember: mainnet is the real Bitcoin network, while testnet is used for testing.

This is one of the most important parts of your teacher's PPT.

A Bitcoin node uses different messages to communicate with other nodes.

Let's understand the important messages one by one, with simple examples.

6.1 Version message

The version message is used when one node introduces itself to another node.

It provides information such as:

  • Protocol version
  • Services supported by the node
  • Timestamp
  • Network address information
  • Other connection-related information

Example:

Node A sends Node B a message:

"Hello! I am a Bitcoin node. This is my protocol version and information about my capabilities."

This is the beginning of the connection handshake.

6.2 Verack message

verack stands for version acknowledgement.

It is sent to acknowledge the version message and complete the initial handshake.

Example:

Node A: "Here is my version information."

Node B: "Here is my version information."

Node A and Node B exchange verack messages to acknowledge the handshake.

6.3 Inv message

inv stands for inventory.

It is used by a node to announce that it knows about certain transactions or blocks.

It generally advertises identifiers or hashes, rather than sending the complete transaction or block data.

Example:

Node A tells Node B:

"I know about a new transaction. Here is its transaction ID."

6.4 Getdata message

getdata is used to request actual transaction or block data that was previously advertised.

Example:

Node B receives an inv message from Node A.

Node B responds:

"Please send me the actual transaction."

It sends a getdata message requesting the transaction.

6.5 Getblocks message

getblocks is used in the older blocks-first synchronisation approach to request block inventory information.

It helps a node discover which blocks are available after a particular known block.

Your teacher's PPT describes it as requesting information about blocks after the last known hash, with a maximum inventory response of 500 blocks in the older method.

6.6 Getheaders message

getheaders requests block headers from another node.

Instead of requesting complete blocks immediately, a node can first obtain the headers.

This is particularly important for headers-first synchronisation.

6.7 Tx message

tx is used to transmit transaction data.

For example, when a node requests a transaction using getdata, the other node can respond with a tx message.

6.8 Block message

block is used to transmit complete block data.

For example, when a node requests a particular block using getdata, the other node can respond with a block message.

6.9 Headers message

headers is used to send requested block headers in response to a getheaders request.

The textbook describes a response containing up to 2,000 block headers.

6.10 Getaddr message

getaddr requests information about other known peers.

A node uses it to discover additional nodes in the network.

6.11 Addr message

addr provides information about known network peers, such as their IP addresses and port numbers.

It can help a node establish additional peer connections.

6.12 Ping and Pong messages

These messages are used to check whether a peer connection is responsive.

  • ping: asks whether the other node is active.
  • pong: responds to the ping.

Example:

Node A: "Are you still connected?"

Node B: "Yes, I am here."

Topic 7: How Do Two Bitcoin Nodes Establish a Connection?

Now let's combine the protocol messages into a real communication process.

Suppose Node A wants to connect with Node B.

What happens?

Step-by-step connection process

Step 1: Node A sends a version message

Node A introduces itself to Node B.

It shares its protocol version and other connection information.

Step 2: Node B sends its version message

Node B responds with its own version information.

Step 3: Both nodes exchange verack messages

They acknowledge the version exchange.

The initial connection handshake is now complete.

Step 4: Nodes exchange getaddr and addr messages

They can request and share information about other known peers.

Step 5: Nodes begin exchanging blockchain information

If they are synchronised, they can listen for new block announcements.

If one node is behind, it requests the missing blockchain information.

Bitcoin node connection handshake
Node A Node B
version → Receives version
Receives version ← version
verack → Acknowledges
Acknowledges ← verack
Connection established
Peer discovery and blockchain synchronisation can proceed.

Bitcoin P2P Handshake Protocol Flow

Two-way version / verack exchange establishing a peer connection
Node A (Initiator)
Client node connecting to peer
1. version → Proto ver, block height, IP, timestamp
Peer version info & capabilities ← 2. version
Peer acknowledges Node A version ← 3. verack
4. verack → Node A acknowledges; handshake complete!
Node B (Responder)
Remote Bitcoin full peer
💡 After the 4-step handshake succeeds, both nodes can safely exchange inv, getdata, tx, and block payloads.

Exam tip: If the question asks how two Bitcoin nodes establish a connection, explain the version and verack handshake first. Then explain getaddr and addr, followed by blockchain synchronisation.

Topic 8: Node Discovery

8.1 What is node discovery?

Node discovery is the process through which a Bitcoin node finds other nodes on the network so that it can establish peer connections.

Think about buying a new phone.

Before you can call someone, you need their phone number.

Similarly, a new Bitcoin node needs information about other available Bitcoin nodes before it can connect to them.

8.2 How does Bitcoin discover nodes?

The textbook explains that Bitcoin Core can discover peers using DNS seeds.

DNS stands for Domain Name System.

DNS is a system that helps translate domain names into network addresses.

In Bitcoin, DNS seeds are services that help a newly started node obtain addresses of available Bitcoin peers.

Example

Suppose Aman starts a new Bitcoin node.

  1. The node starts its Bitcoin software.
  2. It contacts DNS seed services configured by the software.
  3. The DNS seed returns information about available peers.
  4. The node obtains peer addresses.
  5. It attempts to establish connections with those peers.
  6. Once connected, it can discover additional peers through the network.

8.3 What is a DNS seed?

A DNS seed is a service that helps Bitcoin nodes discover other available Bitcoin nodes by providing peer-address information.

Remember that DNS seeds do not control Bitcoin transactions, mining or consensus.

They help with initial peer discovery.

A node may use different port settings depending on its configuration.

8.5 Why is node discovery important?

  1. Allows new nodes to join the Bitcoin network.
  2. Helps nodes find other peers.
  3. Supports transaction propagation.
  4. Supports block propagation.
  5. Helps blockchain synchronisation.

Topic 9: Blockchain Synchronisation

This is another very important topic from your teacher's PPT and the textbook.

9.1 What is blockchain synchronisation?

Blockchain synchronisation is the process through which a Bitcoin node obtains the blockchain information it is missing and updates its local copy to follow the valid chain.

Let's understand it with an example.

Suppose Aman installs Bitcoin software on a new computer.

His computer has no previous Bitcoin blockchain data.

But the Bitcoin network has already been operating for many years.

How will Aman's computer obtain the blockchain?

It connects to existing Bitcoin nodes and downloads the required blockchain information.

This process is called blockchain synchronisation.

9.2 Why is synchronisation required?

A new node needs blockchain information to:

  1. Understand the history of transactions.
  2. Verify blocks and transactions.
  3. Identify the current chain.
  4. Check whether transactions spend valid unspent outputs.
  5. Participate correctly in the Bitcoin network.

Without synchronisation, a new full node cannot independently validate the complete historical chain from its starting point.

9.3 What is Initial Block Download (IBD)?

Initial Block Download (IBD) is the process through which a newly started or significantly unsynchronised Bitcoin node downloads and validates the blockchain data needed to catch up with the network.

Let's take a simple example.

Aman starts a new full node.

  • His computer has no recent blockchain data.
  • It connects to existing Bitcoin peers.
  • It requests blockchain information.
  • It downloads block headers and blocks.
  • It validates the data according to Bitcoin's rules.
  • It catches up with the chain it considers valid.

This initial catch-up process is called IBD.

Important terms

Term Meaning
IBD node The node requesting blockchain information to catch up
Sync node A peer from which the IBD node requests blockchain information
Block header The header information of a block, without the complete block body
Block The complete block data, including its transactions

Your teacher's PPT uses the terms IBD node and sync node to explain the synchronisation process.

Downloads full blocks sequentially one by one from a single peer. If a peer stalls or delivers an invalid block, sync freezes and resources are wasted.
Modern: Headers-First Download
Phase 1: Rapidly downloads all 80-byte block headers to validate the longest PoW chain.
Phase 2: Downloads full block bodies in parallel across dozens of peers simultaneously!

Your textbook explains two approaches to blockchain synchronisation:

  1. Blocks-first approach
  2. Headers-first approach

This is a very important comparison for the examination.

10.1 Blocks-first approach

In the blocks-first approach, a node requests block information and downloads blocks as part of its synchronisation process.

The older process used inventory announcements and block requests.

Working

  1. A new node connects to an existing peer.
  2. It requests block inventory information using getblocks.
  3. The peer responds with an inv message.
  4. The new node requests blocks using getdata.
  5. The peer sends the requested blocks.
  6. The new node processes the received blockchain data.

Your textbook describes this as the older and slower method.

10.2 Headers-first approach

The headers-first approach improves synchronisation by downloading block headers first.

Instead of downloading complete blocks immediately, the node first obtains the chain's header information.

Working

  1. A new node connects to existing peers.
  2. It sends a getheaders message.
  3. The peer responds with a headers message.
  4. The new node validates the received headers.
  5. It obtains the chain structure through the header chain.
  6. It then requests the required full blocks using getdata.
  7. Blocks can be downloaded from multiple available peers.
  8. The node validates the received blocks and catches up with the network.

10.3 Why is headers-first better?

Imagine downloading a large book.

Blocks-first: You start downloading the complete pages directly.

Headers-first: You first obtain the table of contents and chapter structure, and then download the required complete pages.

The second approach helps the node establish the chain of block headers before downloading all the block data.

The textbook explains that headers-first synchronisation was introduced in Bitcoin Core 0.10.0 and improved the synchronisation process compared with the older blocks-first approach.

11.1 What is Stratum?

Stratum is a communication protocol commonly used to connect miners to mining pools.

Before understanding Stratum, let's understand why mining pools are needed.

What is a mining pool?

A mining pool is a group of miners who combine their computational resources to work toward finding valid blocks.

Instead of mining completely independently, multiple miners work under the coordination of a pool.

If the pool successfully finds a block, the reward is distributed among participants according to the pool's payment rules.

Why do miners use Stratum?

Suppose 100 miners are participating in a mining pool.

They need a way to:

  • Receive mining work.
  • Submit their computed results.
  • Communicate with the mining-pool server.
  • Receive updated work when necessary.

Stratum provides a communication mechanism for these tasks.

11.2 Characteristics of Stratum

According to your textbook:

  1. It is a line-based protocol.
  2. It uses TCP sockets.
  3. It uses human-readable JSON-RPC messages.
  4. It is commonly used for communication between miners and mining-pool servers.

C. Exam-ready 10-mark answer: Explain the Bitcoin P2P network

Introduction:

The Bitcoin network is a decentralised peer-to-peer network in which computers called nodes communicate directly with each other. Nodes verify and propagate transactions and blocks, while mining nodes also produce blocks.

Architecture and working:

  1. Bitcoin uses a P2P architecture without depending on a single central server.
  2. Nodes connect to other peers using the Bitcoin network protocol.
  3. Full nodes independently validate transactions and blocks.
  4. SPV nodes download block headers and use Merkle proofs for transaction-inclusion verification.
  5. Nodes exchange messages such as version, verack, inv and getdata.
  6. New nodes discover peers using mechanisms such as DNS seeds.
  7. Nodes synchronise blockchain data through methods such as headers-first synchronisation.
  8. Transactions are propagated between connected peers.
  9. Miners construct candidate blocks and perform Proof of Work.
  10. Valid blocks are independently checked and propagated by other nodes.

Advantages:

  • Decentralised communication.
  • No single central server dependency.
  • Fault tolerance.
  • Distributed transaction and block propagation.
  • Open participation.

Conclusion:

The Bitcoin P2P network provides the communication infrastructure required for transaction exchange, block propagation, verification and decentralised operation.
